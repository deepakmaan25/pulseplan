# PulsePlan — roadmap

Milestones are independently shippable and reviewable. Each row's **Done
when** is the gate to start the next milestone. Don't skip ahead.

Legend: ✅ done · 🟡 in progress · ⬜ not started

## M0 — Foundation

Scaffold the app shell, port design tokens, and stand up the source-of-truth
docs. No product features yet.

| Step                                                                                    | Status |
| --------------------------------------------------------------------------------------- | ------ |
| Init repo + source-of-truth docs (`CLAUDE.md`, `HANDOFF.md`, `roadmap.md`, `README.md`) | ✅     |
| Next.js 15 + TS strict + Tailwind v4 + Geist via `next/font`                            | ✅     |
| Port `pp2-tokens.css` verbatim into `src/styles/tokens.css`                             | ✅     |
| `ThemeProvider` (light/dark/auto, defensive `localStorage`, no-flash inline script)     | ✅     |
| `QueryProvider`, `ToastProvider`, base providers                                        | ✅     |
| ESLint flat config + Prettier + `tsc --noEmit` script                                   | ✅     |
| GitHub Actions CI: typecheck + lint + format:check + Vitest                             | ✅     |
| Vitest smoke test (ThemeProvider)                                                       | ✅     |
| axe-core a11y test on `/playground`                                                     | ✅     |
| PWA manifest (no service worker yet)                                                    | ✅     |

**Done when:** `npm run dev` opens a themed shell; light/dark toggle works
end-to-end; CI passes (typecheck + lint + format:check + smoke + axe).

**Status: 🟡 implementation-complete, awaiting verification gate.** A clean
`npm install` followed by `typecheck` / `lint` / `format:check` / `test` /
`dev` must all pass locally before M0 is closed and M1a begins.

## M1a — Component library

Build every primitive listed in handoff §6 with all interaction states. Wire
a `/playground` route that displays them in both themes.

Primitives: `Button`, `IconButton`, `StatusChip`, `PillarChip`,
`PlatformChip`, `PriorityChip`, `FilterChip`, `AppBar`, `BottomNav`,
`Segmented`, `Surface`, `PostRow`, `BoardCard`, `Sheet` (bottom + animated),
`Snackbar`, `EmptyState`, `KPI`, `Skeleton`.

States per interactive: default, hover, pressed, focus-visible, disabled,
loading.

**Done when:** the playground passes `axe` with zero violations in both
themes; all variants and states render correctly on a real phone.

**Status: 🟡 implementation-complete, awaiting hosted verification.** The
local gate is green (typecheck / lint / format:check / 6 tests including
axe-core in both themes). Visual verification happens against the Vercel
preview built from this push.

## M1b — Static screens

Build all 9 screens with mock data fixtures (mirrors `POSTS2`, `PILLARS2`,
`PLATFORMS2` from the prototype). No persistence.

Screens: Onboarding · Today · Weekly Plan · Monthly Calendar · Board ·
Content Detail · Analytics · Notifications · Settings.

Includes: BottomNav navigation, Quick Capture sheet (state-only), Schedule
sheet (state-only), Snackbar + UNDO plumbing, empty/loading/error per
screen.

**Done when:** the app is fully navigable on a real phone and visually
matches `_handoff/content-planner/project/PulsePlan v2.html`. **First
Vercel preview deploy lands at this checkpoint.**

---

## M2a — Schema + RLS

Supabase project (local CLI + Docker). Migrations for every table in handoff
§8. RLS policies on all tables. Generated TypeScript types. Seed script.
Policy tests assert cross-user reads are denied.

**Done when:** `supabase db reset` produces a usable DB; the policy test
suite is green.

---

## M2b — Auth + onboarding

Supabase magic-link auth. Auth middleware. The 4-step onboarding persists
after each step and resumes from the last completed step on re-entry.

**Done when:** a new user can sign up, complete onboarding, and land on
Today with their profile + pillars persisted.

---

## M2c — Posts + Pillars CRUD

Posts list/detail/create/update/soft-delete with optimistic UI. Pillars
CRUD. TanStack Query wired. Autosave on Detail. Status-change with UNDO.

**Done when:** the loop "capture → schedule → planner → mark published"
persists across reload. **Second Vercel preview deploy lands here.**

---

## M3 — Analytics + Notifications

`post_metrics` manual entry on Published-state detail. Analytics screen
reads real data. `notifications` rows generated by triggers for
**overdue** and **token-expired** events only (the other triggers from
the handoff are v1.1).

**Done when:** a Published post shows entered metrics on the Analytics
screen; an overdue scheduled post produces a notification row.

---

## M4 — Polish + ship

Activity log on the Detail tab. Recurring slot rendering on planner.
Long-press → Schedule sheet on planner. Service worker scaffolding (PWA
manifest already in place from M0). Vercel production deploy + custom
domain. Lighthouse Perf ≥ 90 / A11y = 100.

**Done when:** first real users can use it on a phone.
